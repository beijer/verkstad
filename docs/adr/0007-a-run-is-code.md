# A Run is code: `verkstad run` drives headless sessions

A Run is the `verkstad run` command: TypeScript that works the Frontier one Ticket at a time, giving each implementer, Verifier and conflict finisher a fresh headless `claude -p` session in a worktree the Run makes, and routing on each session's structured report. Every routing rule and budget (one Resume, one Fix round, one finished conflict, one wrap-up) is code under the CLI's test seam. A session is bounded by a dollar budget it is told and sees shrink; its turns and its time are only fuses. We rejected an orchestrator session following a skill's routing prose, which verkstad ran first, because the prose could not be tested, changed in a third of the repo's commits, and grew the orchestrator's context to 650k tokens in a ten-hour Run, while every decision it made was a lookup the CLI could do. We rejected a loop inside one session (the Ralph Wiggum plugin, `/goal`), because a Ticket needs fresh context and a check that runs the Gate, not a judge that reads the transcript; Claude Code's dynamic workflows, because a workflow script cannot run git or the `verkstad` CLI; and its cloud Projects and agent teams, because one has a model as coordinator and needs the cloud, and the other is experimental and gives teammates no worktrees. The evidence is in [docs/research/2026-10-08-orchestration-vs-ralph-loop.md](../research/2026-10-08-orchestration-vs-ralph-loop.md) and [docs/research/2026-10-08-turn-limits-for-headless-agents.md](../research/2026-10-08-turn-limits-for-headless-agents.md).

## Consequences

- Model judgement is in three places only: implementing a Ticket, Verifying it blind to the report, and planning with the owner before a Run. What a Run decides between those is code, and a lesson from reflect becomes a tested branch, not a sentence.
- A Run is serial. Running Tickets side by side brings back conflicts, rebase-voided Verdicts and conflict sessions, and Landing's lock already serializes the Gate; it comes back only when a Run's event log shows the sessions, not the Gate, are where the time goes, and the Frontier has Tickets that touch different code.
- A Run's sessions are not isolated by Claude Code, so its worktree guard does not apply to them, and the plugin's hook explains no guard refusal.
- The model never sees a turn count, so a prompt names no turn limit; a session that ends without a report is resumed once to give one, and failing that its branch decides.
