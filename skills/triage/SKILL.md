# Triage

Move a Project's issues through its five triage labels, with the owner. The labels, by the names used here, and the strings the Project's tracker uses for them are in its `docs/agents/triage-labels.md`; its issue tracker, and whether it triages external pull requests as issues, are in `docs/agents/issue-tracker.md`. The owner you are talking to is the reporter. Name each issue you show the owner `<owner>/<repo>#<n>`, with `<owner>/<repo>` from `gh repo view --json nameWithOwner`.

**Nothing is posted and no label is changed without the owner's yes.** Show them the comment and the label change first. Every comment you post opens with the line `> *This was generated by AI during triage.*`.

## What needs attention

With no issue named, list, oldest first, the open issues with no triage label, those labelled `needs-triage`, and those labelled `needs-info` with a comment since their last triage notes or Park's comment: one line each. The owner picks one.

## One issue

1. **Read** the issue with its comments and labels, `GLOSSARY.md`, the ADRs in its area and the code it touches. Check whether the code already does what it asks; if so, it is a `wontfix` that says where.
2. **Reproduce** a bug from its steps where you can, and note what you saw. A cause you could not confirm is a guess, and is called one.
3. **Recommend** a label, with your reasons, and wait for the owner.
4. **Settle it.** An issue with an open design decision is not made `ready-for-agent`: ask the owner (or record it in an ADR) and write the answer into the brief first. One too big for one implementer session is split as the [Ticket format](../../docs/formats/ticket.md) says, each part an issue of its own.
5. **Apply** the label:
   - `ready-for-agent`: post an [Agent Brief](../../docs/formats/agent-brief.md), saying whether you reproduced the bug.
   - `ready-for-human`: decide with the owner whether it stays theirs or can be written up for an agent. If it stays, post the same brief with a line saying why an agent can't do it.
   - `needs-info`: post triage notes: what is settled so far, and the questions still open, each specific.
   - `wontfix`: close it with a comment saying why.

## A `needs-info` issue

Its open questions are in the latest triage notes, or in a Park's comment (the one ending `Parked: branch …`). Ask the owner each one, a round at a time, then triage the issue with the answers as above. A Parked Ticket keeps its branch, so once it is `ready-for-agent` again the next Run Resumes it.
